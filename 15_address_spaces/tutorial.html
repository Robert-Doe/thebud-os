MODULE 15 — PHASE 2

Per-Process Address Spaces

Two processes. Same virtual address 0x400000. Completely different physical memory. Module 15 gives every process its own CR3 — its own page directory — so they live in isolated universes the MMU enforces in hardware.

01 — The Big Analogy

Head First Moment

Imagine every employee in a company has their own filing cabinet with identical drawer labels: "Inbox," "Projects," "Personal." Two employees both reach into their "Projects" drawer — but they pull out completely different folders because each cabinet is physically separate. The label is the same (virtual address); the physical location differs.

That's per-process address spaces. Process A writes to virtual address 0x400000; process B reads from virtual address 0x400000 — and sees its own data, not A's. The MMU's CR3 register points each process to its own "filing cabinet" (page directory).

02 — Address Space Layout

Every process has this virtual address space layout — but the physical frames behind it are unique to each process:

Process A — CR3 = 0x200000
0x000000
kernel (shared phys)
0x400000
user code (phys A1)
0x800000
user stack (phys A2)
Process B — CR3 = 0x201000
0x000000
kernel (same phys!)
0x400000
user code (phys B1)
0x800000
user stack (phys B2)
The Kernel Is Everywhere

The kernel is mapped into every process's address space at the same virtual addresses. This is necessary so that syscalls (which run in ring 0) can access kernel data and code without switching page directories. The kernel pages are NOT marked PAGE_USER — ring-3 code gets a #PF if it tries to read them.

03 — Creating a New Address Space

/* paging.c */
uint32_t paging_create_address_space(void) {
    uint32_t pd_phys = pmm_alloc_page();
    uint32_t *pd = (uint32_t*)pd_phys;
    memset(pd, 0, PAGE_SIZE);

    /* Copy kernel mappings (PDE[0] — first 4MB identity map) into new PD.
       User PDE entries stay zero = not present. */
    uint32_t *kernel_pd = (uint32_t*)paging_kernel_cr3();
    for (int i = 0; i < 256; i++)      /* first 1GB = kernel region */
        pd[i] = kernel_pd[i];          /* share physical page tables */

    return pd_phys;  /* this becomes the new process's PCB.cr3 */
}

/* Switch to a process's address space */
void paging_switch(uint32_t cr3) {
    __asm__ volatile ("mov %0, %%cr3" : : "r"(cr3) : "memory");
}
Sharing kernel PTEs is safe

We copy the kernel's PDE entries into every new page directory. This means all processes share the same physical page tables for kernel memory — any kernel mapping change is instantly visible to all processes. That's intentional: the kernel is one entity mapped into all address spaces, not duplicated.

04 — Switching Address Spaces

/* process.c — scheduler_tick, updated for address spaces */
uint32_t scheduler_tick(uint32_t current_esp) {
    if (current) current->esp = current_esp;

    struct process *next = pick_next();
    if (!next) return current_esp;

    current = next;
    current->state = PROC_RUNNING;

    /* Update TSS so ring-3→0 transitions use the right kernel stack */
    tss_set_kernel_stack(current->kernel_stack_top);

    /* Switch page directory — invalidates TLB for user pages */
    paging_switch(current->cr3);

    return current->esp;
}
TLB flush on CR3 write

Writing to CR3 automatically flushes the entire TLB (except global pages). This is necessary because the new process's virtual addresses map to different physical frames than the old process's. Without the flush, the CPU would use stale translations from the previous process — a serious security bug where process A could read process B's data.

05 — Graceful #PF Handling

/* isr.c — page fault handler for ring-3 processes */
void page_fault_handler(struct interrupt_frame *f) {
    uint32_t fault_addr;
    __asm__ volatile ("mov %%cr2, %0" : "=r"(fault_addr));

    int is_user = (f->err_code & 0x4); /* U/S bit in error code */

    if (is_user) {
        kprintf("[#PF] User process %u accessed 0x%x — killed\n",
                current->pid, fault_addr);
        process_exit(); /* only THIS process dies, kernel keeps running */
        return;
    }
    /* Kernel #PF = kernel bug = panic */
    kprintf("KERNEL PANIC: #PF at 0x%x EIP=0x%x\n", fault_addr, f->eip);
    for(;;) __asm__("hlt");
}

07 — Brain Exercise

Sharpen Your Pencil

Question: When process A exits and we free its address space with paging_free_address_space(A->cr3), we free all the physical frames backing A's user pages. But the PDE entries for the kernel region point to the same page tables as the kernel's own page directory.

If we blindly walk A's page directory and free every page table, what happens to the shared kernel page tables? How do we know which PTEs are A's private frames vs shared kernel frames?

There Are No Dumb Questions

Q: How does the kernel access user memory in syscalls after this module?
The kernel runs in ring 0, which can access any mapped page regardless of the U/S bit (as long as CR0.WP isn't set — we don't set it). After the context switch, the current process's CR3 is active, so user virtual addresses are valid from the kernel's perspective too. The kernel just dereferences user pointers directly. In production kernels with SMAP (Supervisor Mode Access Prevention), you'd need explicit stac/clac instructions around user memory accesses.
Q: What's ASLR and why don't we have it?
Address Space Layout Randomization randomizes where the stack, heap, and libraries are loaded each run — making exploit offsets unpredictable. We load everything at fixed addresses (code at 0x400000, stack at 0x800000) for simplicity. Adding ASLR would mean picking random base addresses at process creation time, which is straightforward once you have per-process address spaces.
