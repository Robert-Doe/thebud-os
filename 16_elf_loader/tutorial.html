ELF Loader

01 — The Big Analogy

Head First Moment

Think of an ELF file like an IKEA flat-pack box. The box has an instruction sheet (ELF header) that says "this kit has 3 sections — put section A at position X, section B at position Y." The program headers are those instructions. The ELF loader is the person following them: open the box, find each part, place it where the instructions say, then step back and let the finished furniture do its job.

The "furniture" is your user process. The "position" is a virtual address. The "placing" is copying bytes from the ELF file into freshly allocated memory pages.

/* elf.h — the structs we care about */
typedef struct {
    uint8_t  e_ident[16]; /* magic + class + endian + ... */
    uint16_t e_type;      /* ET_EXEC = 2 */
    uint16_t e_machine;   /* EM_386 = 3 */
    uint32_t e_entry;     /* entry point virtual address */
    uint32_t e_phoff;     /* offset to first program header */
    uint32_t e_phentsize; /* size of one program header (32) */
    uint16_t e_phnum;     /* number of program headers */
    /* ... */
} Elf32_Ehdr;

typedef struct {
    uint32_t p_type;   /* PT_LOAD = 1 */
    uint32_t p_offset; /* offset in file */
    uint32_t p_vaddr;  /* virtual address to load at */
    uint32_t p_filesz; /* bytes in file */
    uint32_t p_memsz;  /* bytes in memory (>= filesz; BSS = memsz-filesz) */
    uint32_t p_flags;  /* PF_R=4, PF_W=2, PF_X=1 */
    uint32_t p_align;
} Elf32_Phdr;

03 — The Loader Algorithm

/* elf_loader.c */
uint32_t elf_load(const char *filename, uint32_t *cr3_out) {
    char buf[65536];
    int n = fs_read(filename, buf, sizeof(buf));
    if (n < 0) return 0;

    Elf32_Ehdr *ehdr = (Elf32_Ehdr*)buf;
    /* validate magic */
    if (*(uint32_t*)ehdr->e_ident != 0x464C457F) return 0; /* \x7FELF */

    /* create a fresh address space */
    uint32_t pd = paging_create_address_space();
    *cr3_out = pd;

    /* process each PT_LOAD segment */
    for (int i = 0; i < ehdr->e_phnum; i++) {
        Elf32_Phdr *ph = (Elf32_Phdr*)(buf + ehdr->e_phoff + i * ehdr->e_phentsize);
        if (ph->p_type != 1) continue; /* skip non-PT_LOAD */

        /* allocate pages and map them into the new address space */
        uint32_t vaddr = ph->p_vaddr & ~0xFFF;
        uint32_t pages = (ph->p_memsz + 0xFFF) / PAGE_SIZE;
        for (uint32_t p = 0; p < pages; p++) {
            uint32_t phys = pmm_alloc_page();
            paging_map_user_page(pd, vaddr + p * PAGE_SIZE, phys);
        }
        /* copy file bytes into the mapping (temporarily switch to new PD) */
        paging_switch(pd);
        memcpy((void*)ph->p_vaddr, buf + ph->p_offset, ph->p_filesz);
        memset((void*)(ph->p_vaddr + ph->p_filesz), 0,  /* zero BSS */
               ph->p_memsz - ph->p_filesz);
        paging_switch(paging_kernel_cr3());
    }
    return ehdr->e_entry; /* entry point */
}
The objcopy trick for embedding ELFs

Before the ELF loader can read from BobFS, someone has to put the ELF file there. The Makefile uses objcopy -I binary to embed the compiled user ELF as a blob inside the kernel image with symbols _binary_user_prog_elf_start / _end. At boot, kernel_main calls fs_create("prog.elf", &_binary_...) to write it to disk. After that, sys_exec("prog.elf") reads it back through the ELF loader.

04 — Building the User ELF

# user_linker.ld — tells the linker where user code lives
ENTRY(user_entry)
SECTIONS {
    . = 0x400000;          /* user code base address */
    .text   : { *(.text) }
    .rodata : { *(.rodata) }
    . = 0x401000;
    .data   : { *(.data) }
    .bss    : { *(.bss) }
}
Two linker scripts, two worlds

linker.ld links the kernel at 0x1000 as a flat binary. user_linker.ld links user programs at 0x400000 as ELF32 executables. They're built and linked separately; the kernel never knows the user program's source — only its ELF file on disk.

06 — Brain Exercise

Sharpen Your Pencil

Question: The loader temporarily switches to the new process's CR3 to copy segment data into the mapped pages (paging_switch(pd)). Then it switches back (paging_switch(kernel_cr3)).

What would happen if we forgot to switch back? The next kernel operation that accesses a kernel data structure would be using the new process's page directory — which doesn't have any of the kernel allocations made after paging_create_address_space(). What symptom would you see?

There Are No Dumb Questions

Q: Why ELF32 and not ELF64?
BobOS targets i686 — a 32-bit x86 CPU. ELF64 is for 64-bit binaries. Our GCC cross-compiler uses -m32 which produces ELF32. The structures are simpler (fewer fields, no 64-bit addresses), making the loader easier to write and understand.
Q: What happens if the ELF is corrupted or has the wrong magic?
The loader checks *(uint32_t*)e_ident == 0x464C457F (the "\x7FELF" magic). If it fails, elf_load returns 0 and sys_exec returns an error code. The calling process (exec_stub) sees the error, prints a message, and calls sys_exit(1). The kernel itself is unaffected.
