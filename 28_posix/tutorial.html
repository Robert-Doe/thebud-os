The single question that motivates this module

You've been writing sys_open(), sys_write(), sys_fork() — BobOS-specific wrappers. But every real C program uses open(), write(), fork() and sets errno on failure. POSIX compliance means your kernel can run programs written for any Unix without changing the program. Module 28 adds the translation layer that makes that possible.

01 — The Big Analogy

Head First Moment

Think of POSIX as a wall socket standard. Every device (kernel) and every appliance (program) agrees on the shape of the plug and the voltage. A toaster built in France and a toaster built in Japan both work in a US socket if they follow the standard. POSIX is that standard for operating systems and programs. When BobOS speaks POSIX, programs written for Linux, macOS, or FreeBSD can be cross-compiled for BobOS with no source changes.

The posix.c wrapper layer is the adapter plug. It converts BobOS's internal error codes and calling conventions into the POSIX-standard shape: return -1 on error, set errno to the standard code.

02 — errno: The Contract

The Golden Rule of POSIX Error Handling

Every POSIX function that can fail returns -1 (for int-returning) or NULL (for pointer-returning) on error, AND sets errno to a standard error code. You must check both. Checking only the return value tells you something went wrong. Checking only errno is unreliable (it's not reset on success). Check return value first, then errno.

/* errno.h — standard error codes (POSIX values) */
extern int errno;

#define ENOENT   2   /* No such file or directory */
#define EBADF    9   /* Bad file descriptor       */
#define ENOMEM  12   /* Out of memory             */
#define EINVAL  22   /* Invalid argument          */
#define EAGAIN  11   /* Try again (would block)   */
#define ENOSYS  38   /* Function not implemented  */
/* ... 20 more ... */

The translation layer in posix.c

/* Every POSIX wrapper follows this exact pattern */
static int ret_or_errno(int bobos_rc) {
    if (bobos_rc < 0) {
        errno = map_err(bobos_rc);  /* translate BobOS code to POSIX code */
        return -1;                  /* POSIX always returns -1 on error   */
    }
    errno = 0;          /* POSIX: reset errno to 0 on success */
    return bobos_rc;
}

/* Example: the POSIX open() wrapper */
int open(const char *path, int flags) {
    return ret_or_errno(sys_open(path, flags));
    /* sys_open returns fd on success, SYSCALL_ENOENT (-4) etc. on fail */
    /* open() returns fd on success, -1 on fail with errno set         */
}
Why Does errno Reset to 0 on Success?

A common bug: call a function that succeeds, then check errno and see a non-zero leftover from a previous failed call — and conclude the current call failed. POSIX says "the value of errno shall be defined only after a call for which it is explicitly stated to be set." Resetting to 0 on success is a defensive best practice. glibc does it in every wrapper.

03 — BSD Sockets Over UDP

/* Classic POSIX UDP echo server — works on BobOS too */
#include "posix.h"

void user_main(void) {
    /* Step 1: create a UDP socket */
    int fd = socket(AF_INET, SOCK_DGRAM, 0);
    if (fd < 0) { write(1, "socket: ", 8); exit(1); }

    /* Step 2: bind to port 7 */
    struct sockaddr_in addr = {
        .sin_family = AF_INET,
        .sin_port   = htons(7),
        .sin_addr   = 0,          /* INADDR_ANY */
    };
    if (bind(fd, &addr, sizeof(addr)) < 0) { exit(1); }

    char buf[256];
    struct sockaddr_in peer;
    uint32_t plen = sizeof(peer);

    while (1) {
        /* Step 3: receive */
        ssize_t n = recvfrom(fd, buf, sizeof(buf), 0, &peer, &plen);
        if (n < 0 && errno == EAGAIN) { sys_yield(); continue; }
        if (n < 0) break;

        /* Step 4: echo back */
        sendto(fd, buf, (size_t)n, 0, &peer, sizeof(peer));
    }
    exit(0);
}
This Is Real POSIX Code

The above is the standard BSD socket UDP echo server. The only non-standard line is sys_yield() in the EAGAIN loop (real POSIX programs would use select() or blocking sockets). Every other line compiles on Linux unchanged. That's the goal of POSIX compliance.

04 — select(): Waiting on Multiple File Descriptors

/* posix.h — fd_set is a 32-bit bitmask (supports fds 0–31) */
typedef struct { uint32_t bits; } fd_set;
#define FD_ZERO(s)     ((s)->bits = 0)
#define FD_SET(fd,s)   ((s)->bits |=  (1u << (fd)))
#define FD_ISSET(fd,s) (((s)->bits >> (fd)) & 1u)
/* Waiting for keyboard OR network socket — POSIX select() */
int kbd_fd  = open("/dev/kbd", O_RDONLY);
int sock_fd = socket(AF_INET, SOCK_DGRAM, 0);

fd_set rfds;
FD_ZERO(&rfds);
FD_SET(kbd_fd,  &rfds);
FD_SET(sock_fd, &rfds);

int ready = select(sock_fd + 1, &rfds, NULL, NULL, NULL);
if (ready > 0) {
    if (FD_ISSET(kbd_fd, &rfds))  handle_keyboard();
    if (FD_ISSET(sock_fd, &rfds)) handle_network();
}
select() Is the Original Multiplexed I/O Primitive

Before epoll (Linux 2.6), select() was how every server handled thousands of connections. You give it a bitmask of fds you're interested in; it tells you which ones are ready. BobOS's select() polls (busy-checks) rather than blocking, but the interface is identical. Programs written against our select() will run on Linux with blocking behavior as a bonus.

05 — stat() and lseek(): The Last Two Syscalls

/* SYS_STAT = 26 — get file metadata */
int fstat(int fd, struct stat *st) {
    int rc = syscall(SYS_STAT, fd, (int)st, 0);
    return ret_or_errno(rc);
}

/* Usage: check if fd is a regular file or a device */
struct stat s;
fstat(fd, &s);
if (S_ISREG(s.st_mode))  vga_print("regular file\n");
if (S_ISCHR(s.st_mode))  vga_print("character device\n");
vga_print("size: "); vga_printint(s.st_size); vga_print(" bytes\n");
/* SYS_LSEEK = 27 — seek within a file */
off_t lseek(int fd, off_t offset, int whence) {
    return (off_t)ret_or_errno(syscall(SYS_LSEEK, fd, (int)offset, whence));
}

/* Usage: jump to byte 100, read 10 bytes, then rewind */
lseek(fd, 100, SEEK_SET);
read(fd, buf, 10);
lseek(fd, 0, SEEK_SET);   /* rewind to beginning */

/* Or: find the file size */
off_t size = lseek(fd, 0, SEEK_END);
lseek(fd, 0, SEEK_SET);   /* rewind after sizing */

There Are No Dumb Questions

Q: Why is errno not thread-local in our implementation?
Thread-local storage on x86 uses the FS or GS segment register to point at a per-thread data block. Each context switch must save/restore that segment register and update the TLS pointer. POSIX mandates this — C11 added _Thread_local for exactly this reason. Our errno is a single global int. It's wrong under concurrent access from multiple threads, but correct for single-threaded processes. The fix: store errno in the PCB and expose it via a pointer through the FS segment, exactly as glibc's __errno_location() does.
Q: What does EAGAIN mean? Why does select() return it?
EAGAIN ("try again") means "this would have blocked, but the call was non-blocking." Our select() polls once and returns EAGAIN if no fds are ready — this is what O_NONBLOCK does on a real OS for individual reads. True blocking select() sleeps the process (PROC_WAITING) and wakes it when any watched fd becomes readable. Our yield-loop workaround (while EAGAIN, sys_yield) is functionally equivalent but burns more CPU than a sleeping process would.
Q: Is BobOS now a real Unix?
Almost. Real Unix certification requires: a full POSIX.1-2017 test suite pass (thousands of tests), virtual memory with demand paging to /swap (Module 22 gets close), a fully blocking scheduler, a complete VFS with hard links, directory traversal, and permissions, plus a working C standard library. BobOS passes the conceptual test: you built every major subsystem from scratch and understand what every line does. That's more valuable than certification.
