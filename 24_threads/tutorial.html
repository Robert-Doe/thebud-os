Threads

Lightweight execution units that share everything with the parent: same address space (CR3), same file descriptors, same globals. Each thread gets its own registers, its own kernel stack, and its own entry point. This is the last OS module.

01 — The Big Analogy

Head First Moment

A process is like a self-contained office: its own building (address space), its own filing cabinets (heap, globals), its own phone extension (file descriptors). A thread is like a new desk in that same office — same building, same cabinets, same phone — but a different person sitting there doing different work simultaneously.

Fork creates a new building. Thread create adds a new desk. One is expensive and isolated; the other is cheap and shared. The tradeoff: sharing means you can stomp on each other's work without synchronization.

02 — PCB Gets the is_thread Flag

/* process.h — additions for threads */
struct process {
    /* existing fields ... */
    uint32_t cr3;
    int      pid;
    int      state;

    /* NEW: thread support */
    int      is_thread;           /* 1 = thread, shares cr3 with parent */
    int      owner_pid;           /* PID of the owning process */
    uint32_t user_stack_top;      /* each thread's own user stack VA */

    /* kernel stack is already per-PCB (always was) */
    uint32_t kernel_stack[KSTACK_SIZE];
    uint32_t kernel_esp;

    /* threads don't get their own fd_table or vm_regions —
       they point back to the owner's */
    struct file_descriptor *fd_table;   /* pointer (shared) */
    struct vm_region       *vm_regions; /* pointer (shared) */
};
Pointer Sharing, Not Copying

Instead of copying the fd_table and vm_regions arrays into each thread's PCB, we store a pointer to the owner's arrays. All threads of a process read and write the same fd_table, so open() in thread 1 is immediately visible to thread 2. This is the core of what makes threads "lightweight" — almost no state is duplicated.

03 — thread_create: A Fork That Shares

/* SYS_THREAD_CREATE = 17 */
int sys_thread_create(void (*fn)(void*), void *arg,
                      uint32_t stack_size) {
    struct process *t = alloc_process();

    /* SHARE the address space — same CR3, no copy */
    t->cr3       = current->cr3;
    t->is_thread = 1;
    t->owner_pid = current->pid;

    /* SHARE fd_table and vm_regions (pointer copy) */
    t->fd_table   = current->fd_table;
    t->vm_regions = current->vm_regions;

    /* Allocate a NEW user stack for this thread */
    uint32_t stack_va = find_free_va_range(current, 0, stack_size);
    for (uint32_t off = 0; off < stack_size; off += PAGE_SIZE) {
        uint32_t phys = pmm_alloc_page();
        paging_map(t->cr3, stack_va + off, phys,
                   PAGE_PRESENT | PAGE_WRITE | PAGE_USER);
    }
    t->user_stack_top = stack_va + stack_size;

    /* Set up the fake iret frame: fn(arg) in ring 3 */
    uint32_t *ustack = (uint32_t*)t->user_stack_top;
    *--ustack = (uint32_t)arg;    /* argument */
    *--ustack = 0;                /* fake return address */
    setup_iret_frame(t, (uint32_t)fn, (uint32_t)ustack);

    t->state = PROC_READY;
    return t->pid;   /* thread ID */
}

/* SYS_THREAD_EXIT = 18 */
void sys_thread_exit(void) {
    /* threads don't zombify — just free and disappear */
    current->state = PROC_DEAD;
    /* do NOT free CR3 — other threads/process still own it */
    scheduler_yield_current();
}

04 — The Scheduler Doesn't Care

/* The round-robin scheduler treats threads and processes
   identically — both are PCB entries in the run queue */
void scheduler_tick(void) {
    struct process *next = run_queue_next();
    if (!next || next == current) return;

    /* context switch: save current ESP, load next */
    current->kernel_esp = read_esp();

    /* CR3 only changes if the next entry is a DIFFERENT process */
    if (next->cr3 != current->cr3) {
        asm volatile("mov %0, %%cr3" :: "r"(next->cr3));
        /* TLB auto-flushed on CR3 write */
    }
    /* else: same address space — no TLB flush needed! */

    current = next;
    write_esp(next->kernel_esp);
    /* TSS esp0 updated for ring-3 → ring-0 transitions */
    tss.esp0 = (uint32_t)(next->kernel_stack + KSTACK_SIZE);
}
Switching Between Threads Is Faster

When the scheduler switches between two threads of the same process, next->cr3 == current->cr3, so we skip the CR3 write. No CR3 write means no TLB flush — the entire TLB is still valid. This is the performance win of threads over processes: intra-process context switches are significantly cheaper.

06 — Brain Exercise

Sharpen Your Pencil

The demo above says "shared counter = 2000" but with real concurrent threads it'll often be less — say, 1847. Why? Both threads read counter, both add 1, both write back. If they interleave, one increment is lost. This is a data race.

Fix it using the spinlock from Module 23 (__sync_lock_test_and_set). Then try replacing the spinlock with __sync_fetch_and_add(&counter, 1) — a single atomic instruction. Which is faster for this use case, and why?

There Are No Dumb Questions

Q: If threads share the address space, what happens when a thread segfaults?
A segfault triggers SIGSEGV. Our signal handler (Module 18) delivers it to the faulting thread. If unhandled, sys_thread_exit is called — but since is_thread=1, we only kill that thread, not the entire process. Real implementations send SIGSEGV to the whole thread group (all threads of that process), because a segfault usually means the address space is corrupt for everyone.
Q: What's Thread-Local Storage (TLS)?
Some data needs to be per-thread even though threads share the address space — for example, errno. TLS gives each thread its own copy of designated variables. On x86 this is typically implemented via the FS or GS segment register pointing at a per-thread block. glibc's pthreads uses this extensively. It's a natural next step beyond what we built here.
