01 — The Big Analogy

Head First Moment

VGA text mode is like a giant whiteboard with 2,000 sticky notes on it (80 columns × 25 rows). Each sticky note has two sides: the front says what character to display, and the back says what color. To write on the screen, you just… write to memory. Byte 0 at address 0xB8000 is the character in the top-left. Byte 1 is its color. Byte 2 is the next character. And so on.

No syscalls. No GPU. Just RAM-mapped hardware doing the rendering for you.

In Protected Mode we can't call BIOS int 0x10 anymore — BIOS lives in Real Mode. But we don't need it. The VGA controller has mapped its display buffer into our address space at 0xB8000. We write there, the hardware reads it, the monitor shows it. Simple as writing to an array.

02 — The Framebuffer Layout

Each character cell is 2 bytes: the ASCII character code, followed by a color attribute byte.

uint16_t *vga = (uint16_t *)0xB8000;

/* Write 'A' in white-on-black at position (col=0, row=0) */
vga[0] = (VGA_COLOR(VGA_BLACK, VGA_WHITE) << 8) | 'A';

/* Position (col, row) → index = row * 80 + col */
vga[row * 80 + col] = (attr << 8) | ch;
The Color Byte

The attribute byte encodes both foreground and background color in 4 bits each: [blink|bg_r|bg_g|bg_b|fg_i|fg_r|fg_g|fg_b]. The macro VGA_COLOR(bg, fg) packs them: (bg << 4) | fg. White-on-black is VGA_COLOR(VGA_BLACK, VGA_WHITE) = 0x0F.

The kprintf implementation

/* vga.c — the key pieces */
static int cursor_x = 0, cursor_y = 0;

void vga_putchar(char c) {
    if (c == '\n') { cursor_x = 0; cursor_y++; scroll_if_needed(); return; }
    uint16_t *fb = (uint16_t *)0xB8000;
    fb[cursor_y * 80 + cursor_x] = (vga_color << 8) | (uint8_t)c;
    if (++cursor_x >= 80) { cursor_x = 0; cursor_y++; scroll_if_needed(); }
}

/* kprintf = vga_printf: uses a tiny printf-style formatter,
   calls vga_putchar() for each output character */

03 — Scrolling

When the cursor reaches row 25, you can't just stop. You need to scroll: copy every row up by one, and blank out the last row.

static void scroll_if_needed(void) {
    if (cursor_y < 25) return;
    /* shift every row up by one */
    uint16_t *fb = (uint16_t *)0xB8000;
    for (int i = 0; i < 24 * 80; i++)
        fb[i] = fb[i + 80];
    /* blank the last row */
    for (int i = 24 * 80; i < 25 * 80; i++)
        fb[i] = (vga_color << 8) | ' ';
    cursor_y = 24;
}
Performance Note

This copies 4,000 bytes (2000 uint16_t values) on every scroll. That's fine for a demo kernel — it's imperceptible. Real OSes use double-buffering or hardware scroll registers to do it in a single register write. We keep it simple.

QEMU shows garbage characters?

The color byte and character byte may be swapped. Check your VGA_COLOR macro — it should be (bg << 4) | fg, and the final 16-bit value should be (attr << 8) | ch. The character is the low byte, the attribute is the high byte.

There Are No Dumb Questions

Q: Can I use this to draw pixels, or only text?
Text mode only (Mode 3 / 80×25). To draw pixels you'd need to switch to a VGA graphics mode or use a VESA framebuffer. That's a whole different rabbit hole — and the text mode is plenty for an OS kernel's debug output.
Q: Why not just use serial port output instead?
You could! QEMU can redirect a serial port to your host terminal with -serial stdio. Many real kernels do exactly that for early boot logging. But VGA output is more satisfying — you can see it right in the emulator window.
