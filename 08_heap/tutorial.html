Heap Allocator

The PMM hands out whole 4KB pages. But kernel data structures are tiny — a PCB, a file descriptor, a node. The heap carves those pages into variable-size pieces with kmalloc and kfree.

01 — The Big Analogy

Head First Moment

Imagine a strip of land divided into plots. When someone wants land, you find a big enough free plot, mark part of it as theirs (splitting), and put a sign on it. When they leave, you remove the sign (freeing). If two adjacent plots are now both free, you merge them back into one big plot (coalescing). That way you don't end up with a thousand tiny useless slivers.

That's your heap. The "signs" are block headers — tiny metadata structs prepended to every allocation that record the size and whether the block is free or used.

02 — The Block Header

typedef struct heap_block {
    uint32_t          size;   /* size of the DATA area (not including header) */
    int               free;   /* 1 = free, 0 = used */
    struct heap_block *next;  /* intrusive linked list of all blocks */
} heap_block_t;

/* Layout in memory:
   [ heap_block_t header ][ data area ... ][ heap_block_t header ][ data area ... ]
*/
HDR
used (32B)
HDR
free (128B)
HDR
used (16B)

Every block has a header immediately before its data. The linked list of headers lets kfree and kmalloc walk all blocks.

03 — kmalloc: Split a Free Block

void *kmalloc(uint32_t size) {
    heap_block_t *b = heap_start;
    while (b) {
        if (b->free && b->size >= size) {
            /* split if there's room for another header + at least 4 bytes */
            if (b->size >= size + sizeof(heap_block_t) + 4) {
                heap_block_t *remainder = (heap_block_t*)
                    ((uint8_t*)(b + 1) + size);
                remainder->size = b->size - size - sizeof(heap_block_t);
                remainder->free = 1;
                remainder->next = b->next;
                b->next = remainder;
                b->size = size;
            }
            b->free = 0;
            return (void*)(b + 1);   /* return pointer PAST the header */
        }
        b = b->next;
    }
    return NULL; /* OOM */
}

kfree: Mark Free + Coalesce

void kfree(void *ptr) {
    heap_block_t *b = (heap_block_t*)ptr - 1; /* step back to header */
    b->free = 1;
    /* coalesce: merge with next block if it's also free */
    while (b->next && b->next->free) {
        b->size += sizeof(heap_block_t) + b->next->size;
        b->next  = b->next->next;
    }
}
Why Coalesce?

Without coalescing, a heap that allocates and frees many small blocks ends up with hundreds of tiny free fragments — none big enough for a large allocation. Coalescing merges adjacent free blocks immediately on free, keeping the heap healthy. Production allocators (like glibc's ptmalloc) do bidirectional coalescing using boundary tags; we only coalesce forward, which is enough for a kernel heap.

04 — Initializing the Heap

/* heap.c */
static heap_block_t *heap_start;

void heap_init(uint32_t pages) {
    /* grab 'pages' physical pages from the PMM and use them as heap */
    uint32_t heap_phys = pmm_alloc_page();
    /* (for simplicity: allocate 'pages' contiguous pages) */
    heap_start = (heap_block_t *)heap_phys;
    heap_start->size = pages * 4096 - sizeof(heap_block_t);
    heap_start->free = 1;
    heap_start->next = NULL;
}
After Module 7 (Paging)

In modules that have paging enabled, the heap lives at a fixed virtual address range — e.g. just above kernel_end in the kernel's virtual address space. The same pmm_alloc_page + paging_map_page calls are used to back it with physical frames, but the C code only ever touches the virtual addresses.

06 — Brain Exercise

Sharpen Your Pencil

Question: Our kfree only coalesces with the next block. What about the previous block? If you free block B, and block A (before B) is also free, our code misses the chance to merge them.

How would you fix this? (One approach: scan from heap_start to find the block before B. Another: use boundary tags — a copy of the header at the end of each block so you can walk backwards. Which one does glibc use?)

There Are No Dumb Questions

Q: What's the difference between kmalloc and malloc?
malloc is the user-space C standard library function. kmalloc is our kernel-internal equivalent. They work the same way conceptually, but kmalloc runs in ring 0 with no libc, and it allocates from the kernel heap (not a user process heap). User processes don't call kmalloc — they get their own heap via mmap/sbrk in future modules.
Q: What about thread safety?
Our kernel is single-core and we disable interrupts during critical sections (or rely on the fact that the timer IRQ is the only preemption source). A production SMP kernel would need a spinlock around kmalloc/kfree. Module 24 (Threads) is where concurrency becomes real, but even there our kernel stays single-core for simplicity.
