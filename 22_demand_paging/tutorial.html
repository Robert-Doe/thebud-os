Demand Paging

mmap reserves address space; no pages are allocated. The first access to each page fires a #PF, the kernel faults it in, and execution continues. 4 GB of virtual space, a few MB of actual RAM.

01 — The Big Analogy

Head First Moment

You rent a 10-room house but only furnish the rooms you actually use. The landlord (kernel) hands you the keys to all 10 rooms up front (reserves the virtual address range). You don't move furniture in until you actually enter a room (first access). If you never use room 7, no furniture is ever bought — no RAM ever allocated.

Demand paging is that house. mmap gives you the keys. Page faults are you walking into a room for the first time and calling the furniture store.

02 — vm_region: The VA Range Table

/* vm.h */
#define VM_PROT_R  0x1
#define VM_PROT_W  0x2
#define VM_PROT_X  0x4

struct vm_region {
    uint32_t base;      /* start VA (page-aligned) */
    uint32_t length;    /* size in bytes */
    uint8_t  prot;      /* VM_PROT_R | VM_PROT_W | VM_PROT_X */
    uint8_t  used;
};

#define MAX_VM_REGIONS 32

/* Added to struct process */
struct vm_region vm_regions[MAX_VM_REGIONS];

The vm_region table is just a map of what the process is allowed to access. No physical memory is backing these regions yet.

03 — SYS_MMAP: Reserve Without Allocating

/* syscall_mmap: add a vm_region, return base VA */
uint32_t sys_mmap(uint32_t hint, uint32_t length, uint8_t prot) {
    length = PAGE_ALIGN_UP(length);
    uint32_t base = find_free_va_range(current, hint, length);
    if (!base) return (uint32_t)-1;  /* ENOMEM */

    struct vm_region *r = vm_alloc_region(current);
    r->base   = base;
    r->length = length;
    r->prot   = prot;
    r->used   = 1;

    /* NO physical pages allocated here */
    return base;
}

/* User side */
void *buf = (void*)sys_mmap(0, 1024*1024, VM_PROT_R|VM_PROT_W);
/* buf is valid VA, but touching it fires a page fault */

04 — The Fault Handler: Fault-in Path

void page_fault_handler(struct interrupt_frame *f, uint32_t err) {
    uint32_t fault_addr;
    asm volatile("mov %%cr2, %0" : "=r"(fault_addr));

    int present   = err & 0x1;
    int write     = err & 0x2;

    /* CoW check first (Module 21) */
    if (present && write) { /* ... CoW path ... */ }

    /* Not present: check vm_region table */
    struct vm_region *r = vm_find_region(current, fault_addr);
    if (!r) {
        /* fault outside any mapped region → segfault */
        send_signal(current, SIGSEGV);
        return;
    }
    /* check write permission */
    if (write && !(r->prot & VM_PROT_W)) {
        send_signal(current, SIGSEGV);
        return;
    }
    /* fault-in: allocate a fresh page and map it */
    uint32_t phys = pmm_alloc_page();
    memset((void*)phys, 0, PAGE_SIZE);   /* zero for security */
    uint32_t page_va = fault_addr & ~0xFFF;
    uint32_t flags = PAGE_PRESENT | PAGE_USER
                   | ((r->prot & VM_PROT_W) ? PAGE_WRITE : 0);
    paging_map(current->cr3, page_va, phys, flags);
    /* return → CPU retries the faulting instruction */
}
Zero-Fill Is a Security Requirement

The page we fault in came from the PMM's free pool. It might contain data from a previously freed process — passwords, keys, secrets. We must zero it before mapping it into the new process. POSIX mandates that anonymous mappings are zero-filled. This is why.

06 — Brain Exercise

Sharpen Your Pencil

Demand paging allocates one page per fault. If a process touches a 1 MB region sequentially from bottom to top, that's 256 page faults. Each fault has kernel overhead: context switch in, PD/PT walk, pmm_alloc, memset, map, TLB flush, context switch out.

Linux uses "readahead" — on a fault at address X, it pre-maps X+1 and X+2 as well, gambling that sequential access is likely. Could you implement a simple version? What's the downside of pre-mapping too aggressively?

There Are No Dumb Questions

Q: ELF loading in Module 16 mapped pages eagerly. Can demand paging replace that?
Yes — production loaders use mmap with VM_PROT_R|VM_PROT_X for the text segment and let page faults bring in ELF pages from disk on first use. Our BobFS doesn't yet support file-backed mappings (we'd need a "file offset" field in vm_region), but the architecture is exactly the same. The "anonymous" demand paging here is step one.
Q: What happens when we run out of physical memory?
Right now: pmm_alloc_page returns 0, we map address 0 (catastrophic). A real OS invokes the page eviction / swap path — it picks a victim page, writes it to disk, frees the frame, then maps the new page. We skip swapping in BobOS; OOM kills the process instead.
