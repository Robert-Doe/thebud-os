Copy-on-Write Fork

Why copy the entire address space when the child might just call exec? CoW turns fork from an O(pages) operation into an O(1) operation. Pages are shared until someone writes — only then does a copy happen.

01 — The Big Analogy

Head First Moment

Imagine you inherit a recipe book from a parent. Instead of photocopying every page immediately, you just share the original. If you want to modify a recipe, then you photocopy that one page. This is Copy-on-Write: share first, copy only when forced. You might never modify most pages — why pay to copy them upfront?

For fork + exec, the child immediately throws away its address space to load a new program. Without CoW it paid to copy all of the parent's pages for nothing. With CoW, fork costs almost nothing.

02 — PMM Gets Reference Counts

/* pmm.h — physical memory manager gains refcounts */
extern uint8_t pmm_refcounts[TOTAL_FRAMES];

static inline void pmm_incref(uint32_t frame) {
    pmm_refcounts[frame]++;
}

/* returns 1 if frame was freed */
static inline int pmm_decref(uint32_t frame) {
    if (--pmm_refcounts[frame] == 0) {
        pmm_free_page(frame * PAGE_SIZE);
        return 1;
    }
    return 0;
}

/* pmm_alloc_page now initialises refcount = 1 */
uint32_t pmm_alloc_page(void) {
    uint32_t addr = _pmm_alloc_inner();
    pmm_refcounts[addr / PAGE_SIZE] = 1;
    return addr;
}
Why uint8_t?

A single physical frame is rarely shared by more than 255 processes at once. Using a full 32-bit int would waste 4× the memory. If you actually need more than 255 sharers (think huge shared libraries), bump it to uint16_t. For BobOS, uint8_t is fine.

03 — Fork: Mark Pages RO Instead of Copying

/* Old fork: deep-copied every page — expensive */
/* New CoW fork: mark both parent and child pages read-only */

int process_fork_cow(void) {
    struct process *child = alloc_process();
    child->cr3 = paging_create_empty();

    /* walk parent's page directory */
    uint32_t *parent_pd = (uint32_t*)current->cr3;
    for (int pdi = 0; pdi < 1024; pdi++) {
        if (!(parent_pd[pdi] & PAGE_PRESENT)) continue;
        if (pdi >= KERNEL_PD_START) {
            /* kernel region: share directly, no CoW */
            child_pd[pdi] = parent_pd[pdi];
            continue;
        }
        uint32_t *pt = (uint32_t*)(parent_pd[pdi] & ~0xFFF);
        uint32_t *child_pt = alloc_page_table();
        for (int pti = 0; pti < 1024; pti++) {
            if (!(pt[pti] & PAGE_PRESENT)) continue;
            uint32_t frame = pt[pti] >> 12;
            /* mark BOTH parent and child entries read-only */
            pt[pti]       &= ~PAGE_WRITE;
            pt[pti]       |= PAGE_COW;   /* custom bit 9 */
            child_pt[pti]  = pt[pti];    /* copy the PTE (same phys frame) */
            pmm_incref(frame);            /* now two owners */
        }
        child_pd[pdi] = (uint32_t)child_pt | PAGE_PRESENT | PAGE_USER;
    }
    flush_tlb_full();   /* must invalidate parent's RO entries */
    /* set up child's fake iret frame with EAX=0 */
    setup_child_frame(child, 0);
    return child->pid;
}

04 — The Write Fault: Doing the Actual Copy

/* page_fault_handler — now checks for CoW fault */
void page_fault_handler(struct interrupt_frame *f, uint32_t err) {
    uint32_t fault_addr;
    asm volatile("mov %%cr2, %0" : "=r"(fault_addr));

    /* bit 1 = write fault, bit 0 = present */
    int write_fault  = err & 0x2;
    int present      = err & 0x1;

    if (present && write_fault) {
        /* page is present but read-only — check CoW bit */
        uint32_t *pte = paging_get_pte(current->cr3, fault_addr);
        if (*pte & PAGE_COW) {
            cow_copy_page(pte);
            return;   /* retry the faulting instruction */
        }
    }
    /* not a CoW fault → real fault, kill or panic */
    kill_process_or_panic(current, fault_addr, err);
}

void cow_copy_page(uint32_t *pte) {
    uint32_t old_frame = (*pte) >> 12;
    /* allocate fresh frame, copy content */
    uint32_t new_phys = pmm_alloc_page();   /* refcount=1 */
    memcpy((void*)new_phys, (void*)(old_frame * PAGE_SIZE), PAGE_SIZE);
    /* decrement old frame's refcount */
    pmm_decref(old_frame);
    /* rewrite PTE: new frame, writable, clear CoW bit */
    *pte = (new_phys) | PAGE_PRESENT | PAGE_WRITE | PAGE_USER;
    flush_tlb_page(new_phys);
}
The Retry Is Automatic

After the fault handler returns, the CPU retries the faulting instruction. The PTE now points to a private writable copy, so the write succeeds — the user process never knows a fault happened. This is the magic of page-fault-based CoW: zero intrusion into user code.

06 — Brain Exercise

Sharpen Your Pencil

After a CoW fork, the parent still has its stack pages marked RO+CoW. The parent's very next function call pushes a return address onto the stack — triggering a CoW fault on its own stack page. Is that a problem? How do real kernels avoid redundant CoW on a page that has only one owner (refcount=1)?

Hint: check the refcount inside cow_copy_page. If it's already 1, you can skip the copy and just make the page writable again. Why is this safe?

There Are No Dumb Questions

Q: What's PAGE_COW? Is that a real CPU bit?
No — x86 PTEs have some "available" bits (bits 9–11) that the CPU ignores. We hijack bit 9 as our CoW marker. The CPU only looks at the standard bits (P, R/W, U/S, etc.) — our custom bit is invisible to it. The kernel reads it during page fault handling to distinguish CoW faults from real access violations.
Q: What about the TLB? Won't the old writable mapping be cached?
Yes — after marking parent pages RO during fork, we flush the entire TLB with a CR3 reload (or INVLPG per page). If we don't, the CPU might serve a write from its cached RW entry, bypassing the fault entirely. TLB flush is non-negotiable after changing page protections.

07 — What's Next

Up Next: Module 22 — Demand Paging

CoW defers copying; demand paging defers allocation. When a process calls mmap, no physical pages are allocated yet — the kernel just records the mapping in a vm_region table. Pages are faulted in one at a time, on first access. This is how modern OSes handle multi-gigabyte virtual address spaces on limited RAM.
