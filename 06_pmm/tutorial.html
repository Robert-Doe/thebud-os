MODULE 06 — PHASE 1

Physical Memory Manager

Before you can allocate anything — heap blocks, page tables, process stacks — you need to know which 4KB chunks of RAM are free. The PMM is a single bitmap that answers that question in O(1).

01 — The Big Analogy

Head First Moment

Imagine a hotel with 16,384 rooms. The receptionist keeps a clipboard with one checkbox per room: checked = occupied, unchecked = free. When a guest arrives, the receptionist scans the clipboard top-to-bottom, finds the first unchecked box, marks it, and hands over that room key. When the guest leaves, the box gets unchecked again.

That clipboard is your PMM. Each checkbox is one bit. Each room is one 4KB physical page frame. The whole "clipboard" is only 2KB of RAM for a 64MB system.

02 — The Bitmap

The bitmap is a flat array of uint32_t words. Each bit represents one 4KB frame. Bit = 0 means free, bit = 1 means allocated.

#define PAGE_SIZE    4096
#define MAX_FRAMES   16384          /* 64 MB / 4 KB */

static uint32_t bitmap[MAX_FRAMES / 32]; /* 512 uint32_t = 2 KB */

/* Mark frame as used */
static void set_bit(uint32_t frame) {
    bitmap[frame / 32] |=  (1u << (frame % 32));
}
/* Mark frame as free */
static void clear_bit(uint32_t frame) {
    bitmap[frame / 32] &= ~(1u << (frame % 32));
}
/* Test if frame is used */
static int test_bit(uint32_t frame) {
    return !!(bitmap[frame / 32] & (1u << (frame % 32)));
}

03 — The Three Key Functions

void pmm_init(uint32_t total_mem, uint32_t kernel_end_phys) {
    total_frames = total_mem / PAGE_SIZE;
    /* mark everything used (safe default) */
    memset(bitmap, 0xFF, sizeof(bitmap));
    /* free frames above the kernel */
    uint32_t first_free = (kernel_end_phys + PAGE_SIZE - 1) / PAGE_SIZE;
    for (uint32_t i = first_free; i < total_frames; i++)
        clear_bit(i);
}

uint32_t pmm_alloc_page(void) {
    for (uint32_t i = 0; i < total_frames; i++) {
        if (!test_bit(i)) { set_bit(i); return i * PAGE_SIZE; }
    }
    return 0; /* OOM */
}

void pmm_free_page(uint32_t phys_addr) {
    clear_bit(phys_addr / PAGE_SIZE);
}
The kernel_end trick

kernel_end_phys comes from the linker symbol &kernel_end set in linker.ld (Module 2). Everything below that address is kernel code/data — mark it used. Everything above is yours to give out. This is why the linker symbol matters so much.

Module 21 adds refcounts

In Module 21 (Copy-on-Write), we add pmm_refcounts[MAX_FRAMES] and pmm_incref() / pmm_decref(). Multiple page tables can point to the same physical frame; the frame is only freed when its refcount drops to zero. The bitmap stays — refcounts sit alongside it.

04 — Why Not Just Use malloc?

The Chicken-and-Egg Problem

malloc (or our kernel's kmalloc) needs to carve blocks out of a heap. But the heap itself needs physical pages to live on. The PMM is the bottom of the stack — it allocates the raw physical pages that the heap (Module 8) then subdivides into smaller chunks. You can't have kmalloc without the PMM.

There Are No Dumb Questions

Q: Why 4KB pages? Why not 1KB or 1MB?
4KB is the granularity the x86 MMU uses for its two-level page tables. You could use 4MB "huge pages" (the PSE flag), but they waste memory for small allocations. 4KB is the sweet spot that hardware enforces and that Linux/Windows both use.
Q: What happens if pmm_alloc_page returns 0?
Physical address 0 is the zero page — used by the BIOS interrupt vector table. We pre-mark it as used in pmm_init, so returning 0 unambiguously means "out of memory." Callers check for 0 and panic or return an error up the chain.
