File System (BobFS)

01 — The Big Analogy

Head First Moment

Think of BobFS like a filing cabinet with exactly 32 labeled folders. Each folder (inode) has a name tag and a note saying which drawer (data block) holds the actual papers. The first drawer in the cabinet is the index card listing all folders (superblock). To find a file: read the index card, find the folder name, go to that drawer.

No trees, no directories, no symbolic links. Just a flat list of files. It's the simplest possible thing that deserves the name "filesystem."

/* Inode: fixed-size metadata for one file */
typedef struct {
    char     name[32];    /* filename */
    uint32_t size;        /* file size in bytes */
    uint32_t start_lba;   /* first disk sector of file data */
    uint8_t  valid;       /* 1 = slot occupied */
} bobfs_inode_t;

/* Superblock: sits at sector 0 */
typedef struct {
    uint32_t magic;       /* 0xB0B0F5 — "BobFS" */
    uint32_t file_count;
    bobfs_inode_t inodes[32];
} bobfs_super_t;

03 — ATA PIO: Reading from Disk

ATA PIO (Programmed I/O) is the oldest, simplest way to talk to an IDE disk. No DMA, no interrupts — just port I/O: write the sector number to ports, wait for the drive to be ready, read 256 words of data.

/* disk.c — read one 512-byte sector from LBA address */
void disk_read_sector(uint32_t lba, uint8_t *buf) {
    outb(0x1F6, 0xE0 | ((lba >> 24) & 0x0F)); /* drive + LBA bits 27-24 */
    outb(0x1F2, 1);                             /* sector count = 1 */
    outb(0x1F3, lba & 0xFF);                   /* LBA low */
    outb(0x1F4, (lba >> 8)  & 0xFF);           /* LBA mid */
    outb(0x1F5, (lba >> 16) & 0xFF);           /* LBA high */
    outb(0x1F7, 0x20);                          /* command: READ SECTORS */

    /* poll until DRQ (data ready) bit is set */
    while (!(inb(0x1F7) & 0x08));

    /* read 256 16-bit words = 512 bytes */
    for (int i = 0; i < 256; i++)
        ((uint16_t*)buf)[i] = inw(0x1F0);
}
Why PIO and Not DMA?

DMA (Direct Memory Access) lets the disk controller write data directly to RAM without CPU involvement — much faster for large transfers. But it requires setting up a DMA controller, physical addresses, and bus mastering — hundreds of extra lines of code. ATA PIO is 30 lines and works in QEMU perfectly. We're learning filesystem concepts, not disk controller optimization.

04 — The Three Key FS Functions

/* fs.c */

/* Read a file by name into buf (up to 'size' bytes) */
int fs_read(const char *name, char *buf, int size) {
    for (int i = 0; i < 32; i++) {
        if (!super.inodes[i].valid) continue;
        if (strcmp(super.inodes[i].name, name) != 0) continue;
        /* found it — read its sectors */
        uint32_t lba = super.inodes[i].start_lba;
        int to_read = MIN(size, super.inodes[i].size);
        /* ... read sectors into buf ... */
        return to_read;
    }
    return -1; /* not found */
}

/* Create a file from a memory buffer */
int fs_create(const char *name, const char *data, int size);

/* Delete a file (marks inode invalid, reclaims nothing — flat FS) */
int fs_delete(const char *name);
Module 16 depends on this directly

The ELF loader (Module 16) calls fs_read("hello.elf", buf, size) to load a user program from disk. BobFS is the reason user programs can live on disk instead of being compiled into the kernel image. Every sys_exec() in Modules 16–24 calls fs_read under the hood.

06 — Brain Exercise

Sharpen Your Pencil

Question: BobFS stores all inodes in the superblock (in RAM after fs_init()). When you create a file and call fs_create(), does BobFS immediately write the updated superblock back to disk?

If the kernel panics between fs_create() and the superblock write-back, what happens to the file on the next boot? This is the classic filesystem consistency problem — how do real filesystems (ext4, NTFS) solve it?

There Are No Dumb Questions

Q: Why not use FAT or ext2 instead of inventing BobFS?
Implementing FAT or ext2 correctly requires handling clusters, FAT chains, directory entries, timestamps, permissions, and journaling — thousands of lines. BobFS has 32 inodes and no directories. The point of this module is to understand disk I/O and filesystem concepts, not to implement a production FS. Once you understand BobFS, reading the ext2 spec is much easier.
Q: How does the kernel know where free disk space starts?
BobFS tracks the "next available LBA" in the superblock. When creating a file, it appends data after all existing files. There's no space reclamation when files are deleted — deleted file space is wasted. A real FS would use a free-block bitmap like our PMM does for RAM.
