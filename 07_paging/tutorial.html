Virtual Memory & Paging

01 — The Big Analogy

Head First Moment

Think of virtual addresses like PO Box numbers at a post office. You mail a letter to "PO Box 4000" — you don't know (and don't care) which physical shelf holds that box. The postmaster (MMU) looks up PO Box 4000 in a directory, finds it maps to shelf 7, row 3, and delivers the letter there.

Two processes can both have a "PO Box 4000" — they just map to different physical shelves. That's virtual address isolation: two programs at the same virtual address, completely separated in physical RAM.

02 — How a 32-bit Virtual Address Splits

The MMU splits every 32-bit address into three fields and uses them as indices to walk the two-level page table hierarchy:

bits 31–22 (10 bits)Page Dir Index
bits 21–12 (10 bits)Page Table Index
bits 11–0 (12 bits)Page Offset
Virtual address 0x00401000:
  bits 31-22 = 0x001  → Page Directory entry [1]   (covers 0x00400000–0x007FFFFF)
  bits 21-12 = 0x001  → Page Table entry [1]        (the second 4KB in that 4MB)
  bits 11-0  = 0x000  → Offset 0 within the page

Walk:
  CR3                    → physical addr of Page Directory
  PD[1]                  → physical addr of Page Table for PDE[1]
  PT[1]                  → physical frame addr
  physical frame + 0x000 → the actual RAM byte

03 — PDE and PTE Flags

#define PAGE_PRESENT   0x001   /* page is mapped (must be set) */
#define PAGE_WRITE     0x002   /* page is writable */
#define PAGE_USER      0x004   /* ring-3 can access (MUST be set in BOTH PDE and PTE) */

/* Map virtual page virt → physical frame phys for the kernel */
void paging_map_page(uint32_t *pd, uint32_t virt, uint32_t phys, uint32_t flags) {
    uint32_t pdi = virt >> 22;
    uint32_t pti = (virt >> 12) & 0x3FF;

    if (!(pd[pdi] & PAGE_PRESENT)) {
        uint32_t pt_phys = pmm_alloc_page();
        memset((void*)pt_phys, 0, PAGE_SIZE);
        pd[pdi] = pt_phys | PAGE_PRESENT | PAGE_WRITE | (flags & PAGE_USER);
    }

    uint32_t *pt = (uint32_t*)(pd[pdi] & ~0xFFF);
    pt[pti] = phys | PAGE_PRESENT | flags;
}
The PAGE_USER Gotcha

PAGE_USER must be set in both the PDE and the PTE for ring-3 to access a page. Set it only in the PTE and ring-3 gets a #PF anyway — the CPU checks the PDE first. This is the single most common paging bug in student kernels.

04 — Turning On the MMU

void paging_init(void) {
    uint32_t *pd = (uint32_t*)pmm_alloc_page();
    memset(pd, 0, PAGE_SIZE);

    /* Identity-map the first 4MB (kernel + VGA buffer at 0xB8000) */
    paging_map_4mb_identity(pd, 0x00000000);

    /* Load CR3 with the page directory physical address */
    __asm__ volatile ("mov %0, %%cr3" : : "r"((uint32_t)pd));

    /* Set PG bit in CR0 to enable paging */
    uint32_t cr0;
    __asm__ volatile ("mov %%cr0, %0" : "=r"(cr0));
    cr0 |= 0x80000000;
    __asm__ volatile ("mov %0, %%cr0" : : "r"(cr0));
    /* Paging is now ON. Every memory access goes through the MMU. */
}
Identity Mapping

We map virtual 0x00000000–0x003FFFFF → physical 0x00000000–0x003FFFFF. This means the kernel's own virtual addresses equal its physical addresses — so the code that just wrote to CR0 can keep running without the rug being pulled out. Without this, the first instruction after enabling paging would try to fetch from a virtual address that maps to garbage.

05 — The Page Fault Handler

/* isr.c — registered as handler for vector 14 */
void page_fault_handler(struct interrupt_frame *f) {
    uint32_t fault_addr;
    __asm__ volatile ("mov %%cr2, %0" : "=r"(fault_addr));

    kprintf("[#PF] at 0x%x  EIP=0x%x  err=0x%x\n",
            fault_addr, f->eip, f->err_code);
    /* err_code bits: P=present, W=write, U=user */
    /* For now: kill the process (Module 15 makes this smarter) */
    process_exit();
}

07 — Brain Exercise

Sharpen Your Pencil

Question: After enabling paging, the kernel's page directory itself sits at some physical address. To modify the page tables (add a new mapping), you need to write to that physical address. But all addresses are now virtual. How do you write to a physical address when paging is on?

Think: if the kernel is identity-mapped (virtual = physical for the first 4MB), and the page directory is within the first 4MB, what does that mean for accessing it by pointer?

There Are No Dumb Questions

Q: What's the TLB and why does it matter?
The Translation Lookaside Buffer is a CPU cache of recent virtual→physical translations. It's fast, but stale. When you modify a page table entry, you must flush the TLB for that address — otherwise the CPU keeps using the old translation. The cheapest way: write any value to CR3 (mov cr3, cr3). This flushes the entire TLB.
Q: Why two levels? Why not just one big page table?
A single-level page table for a 32-bit address space needs 1M entries × 4 bytes = 4MB of RAM per process, always allocated. With two levels, you only allocate a Page Table when a PDE is actually used — most of the 4GB space is empty, so most page tables don't exist. Two levels makes sparse address spaces cheap.
