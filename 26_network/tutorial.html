Prerequisites — what you must already own

What to be comfortable with before opening ne2000.c

You need to understand inb() / outb() — the CPU I/O port instructions that talk to ISA hardware. The NE2000 is entirely port-mapped: no memory-mapped registers, just reads and writes to I/O addresses 0x300–0x31F. You also need the scheduler from Module 25, because net_poll() is driven by the kernel timer tick.

01 — The Big Analogy

Head First Moment

A network stack is like a postal system with five floors in a building. The mailroom (NIC) receives physical letters. The courier (Ethernet) carries envelopes within the building. The address department (IP) reads the ZIP code and decides which office to deliver to. The department secretary (UDP) sorts by desk number (port). The employee (your app) reads the letter.

Every incoming packet climbs all five floors — NIC → Ethernet → IP → UDP → socket buffer. Every outgoing packet descends all five floors. Each layer adds or strips its own header. That's it. There's no magic.

02 — The NE2000 Ring Buffer

The NIC Has Its Own Memory

The NE2000 has 16 KB of on-chip SRAM. Your CPU cannot read it directly — you must use Remote DMA (RDMA): set up a source address and byte count in the NIC registers, then read/write 16-bit words through the DATA port. Think of it as a slow serial transfer rather than a memcpy.

/* ne2000.c — Remote DMA read: copy len bytes from NIC memory at addr */
static void ne_remote_read(uint16_t addr, void *buf, uint16_t len) {
    outb(NE_CR,    NE_CR_PAGE0 | NE_CR_RD2 | NE_CR_START);
    outb(NE_RBCR0, len & 0xFF);   /* byte count low  */
    outb(NE_RBCR1, len >> 8);    /* byte count high */
    outb(NE_RSAR0, addr & 0xFF); /* source addr low  */
    outb(NE_RSAR1, addr >> 8);   /* source addr high */
    outb(NE_CR,    NE_CR_PAGE0 | NE_CR_RD0 | NE_CR_START);

    uint16_t *p = (uint16_t *)buf;
    for (uint16_t i = 0; i < (len + 1) / 2; i++)
        p[i] = inw(NE_DATA);  /* read one 16-bit word at a time */
}

The RX Ring Buffer

/* NIC ring buffer layout (256-byte pages):
 *
 *  Page 0x40-0x45  TX buffer (for transmit)
 *  Page 0x46-0x7F  RX ring  (for receive)
 *
 * BNRY: last page the CPU has finished reading (boundary pointer)
 * CURR: page the NIC is currently writing received packets to
 *
 * A packet is available when: (BNRY + 1) != CURR
 *
 * Each received packet is prepended with a 4-byte header:
 *   [status][next_page][len_lo][len_hi]
 */

struct ne_rx_hdr {
    uint8_t  status;      /* 0x01 = received OK */
    uint8_t  next_page;   /* page after this packet */
    uint16_t len;         /* total length including this header */
} __attribute__((packed));

03 — IPv4: The IP Header in 20 Bytes

/* ip.h — the complete IPv4 header */
struct ip_hdr {
    uint8_t  ver_ihl;    /* high nibble=4 (IPv4), low nibble=5 (20 bytes) */
    uint8_t  tos;        /* type of service — we always send 0 */
    uint16_t total_len;  /* IP header + payload, big-endian */
    uint16_t id;         /* fragment ID — we increment per packet */
    uint16_t frag_off;   /* fragment offset — always 0 (no fragmentation) */
    uint8_t  ttl;        /* time to live — we send 64 */
    uint8_t  proto;      /* 17=UDP, 1=ICMP, 6=TCP */
    uint16_t checksum;   /* one's complement checksum of header only */
    uint32_t src;        /* source IP, big-endian */
    uint32_t dst;        /* destination IP, big-endian */
} __attribute__((packed));   /* 20 bytes exact — no padding allowed */
Why __attribute__((packed))?

The compiler is allowed to insert padding between struct fields to align them for fast CPU access. For example, it might put 2 bytes of padding after uint8_t proto to align uint32_t src on a 4-byte boundary. That padding would corrupt the packet — the network expects exact byte positions. packed disables all padding. Every network protocol struct in a real OS uses it.

The IP Checksum — One's Complement Sum

uint16_t ip_checksum(const void *data, uint16_t len) {
    const uint16_t *p = (const uint16_t *)data;
    uint32_t sum = 0;

    while (len > 1) { sum += *p++; len -= 2; }
    if (len) sum += *(const uint8_t *)p;  /* odd byte */

    /* Fold 32-bit sum into 16 bits by adding the carry */
    while (sum >> 16) sum = (sum & 0xFFFF) + (sum >> 16);

    return (uint16_t)(~sum);  /* one's complement */
}
How to Verify: Checksum of a Valid Packet Should be 0xFFFF

If you compute ip_checksum() over a received IP header (including the checksum field itself), the result should be 0xFFFF (all ones). That's the one's complement identity: when you sum a number and its complement, you get all ones. RFC 791 mandates this. If the result is anything else, the packet is corrupt — drop it.

04 — UDP: The Simplest Transport Protocol

/* udp.h — 8-byte UDP header */
struct udp_hdr {
    uint16_t src_port;
    uint16_t dst_port;
    uint16_t length;    /* UDP header (8 bytes) + data */
    uint16_t checksum;  /* 0 = checksum disabled (legal for UDP over IPv4) */
} __attribute__((packed));
/* udp.c — receiving a datagram */
void udp_input(const uint8_t *seg, uint16_t len, uint32_t src_ip) {
    const struct udp_hdr *udp = (const struct udp_hdr *)seg;
    uint16_t dst_port = ntohs(udp->dst_port);

    /* Find the socket bound to this port */
    for (int i = 0; i < UDP_MAX_SOCKETS; i++) {
        if (sockets[i].bound && sockets[i].port == dst_port) {
            /* Copy data into the socket's single receive slot */
            struct udp_rx_entry *rx = &sockets[i].rx;
            rx->src_ip   = src_ip;
            rx->src_port = ntohs(udp->src_port);
            rx->data_len = ntohs(udp->length) - sizeof(struct udp_hdr);
            /* memcpy the payload */
            for (uint16_t j = 0; j < rx->data_len; j++)
                rx->data[j] = seg[sizeof(struct udp_hdr) + j];
            rx->valid = 1;
            return;
        }
    }
    /* No socket bound to this port — silently discard */
}

05 — Byte Order: The Silent Bug Waiting to Happen

Big-Endian vs. Little-Endian — This Will Bite You

x86 is little-endian: the number 0x0800 is stored in memory as [00][08]. The network is big-endian: the same number is transmitted as [08][00]. Every multi-byte field in an IP or UDP header must be converted when reading or writing.

/* net.h — byte-order conversion (no libc needed) */
static inline uint16_t htons(uint16_t v) {
    return (uint16_t)((v >> 8) | (v << 8));
}
static inline uint32_t htonl(uint32_t v) {
    return ((v & 0xFF000000u) >> 24) | ((v & 0x00FF0000u) >> 8)
         | ((v & 0x0000FF00u) <<  8) | ((v & 0x000000FFu) << 24);
}
/* ntohs / ntohl are the same operation */
static inline uint16_t ntohs(uint16_t v) { return htons(v); }
static inline uint32_t ntohl(uint32_t v) { return htonl(v); }
The Rule: Every Network Multi-Byte Field Needs htons/htonl on Write, ntohs/ntohl on Read

If you forget one, the packet silently has the wrong port or wrong IP address. Wireshark will show you "destination port: 8704" when you meant 34. The fix is always the same: add the missing conversion. This is by far the most common networking bug in first-time drivers.

06 — User-Space Echo Server

/* user_prog.c — UDP echo server on port 7 */
#include "syscall.h"

void user_main(void) {
    /* Bind a socket to port 7 (well-known echo port) */
    int sock = syscall(SYS_SOCKET, 7, 0, 0);
    if (sock < 0) { vga_print("bind failed\n"); sys_exit(1); }

    vga_print("[echo] listening on UDP port 7\n");

    uint8_t buf[256];
    uint32_t src_ip;
    uint16_t src_port;

    while (1) {
        /* Poll for a packet — blocks by yielding until one arrives */
        int n;
        while ((n = syscall(SYS_RECVFROM, sock, (int)buf, (int)&src_ip)) == 0)
            sys_yield();

        /* Echo it back */
        vga_print("[echo] got "); vga_printint(n); vga_print(" bytes\n");
        syscall(SYS_SENDTO, (int)src_ip, (int)(7 | ((uint32_t)src_port<<16)), (int)buf);
    }
}

08 — Brain Exercise

Sharpen Your Pencil

You send a UDP packet with src_port=1234, dst_port=7, payload "hello\n" (6 bytes). Draw the complete byte layout of what hits the wire — Ethernet header (14 bytes) + IP header (20 bytes) + UDP header (8 bytes) + payload (6 bytes) = 48 bytes total. What is the value at byte offset 36 (0-indexed)? Write it before scrolling.

Answer: byte 36 is the start of the UDP header's src_port field. In big-endian, port 1234 = 0x04D2, so byte 36 = 0x04 and byte 37 = 0xD2. If you got this right, you can now read a Wireshark hex dump without needing the column labels.

There Are No Dumb Questions

Q: Why is ARP skipped? Don't we need it to send to an IP address?
ARP resolves an IP address to a MAC address by broadcasting "who has IP X?" and waiting for the reply. We skip it by sending to the broadcast MAC (FF:FF:FF:FF:FF:FF) instead. Switches and routers on a real LAN would see this as excessive broadcast traffic, but QEMU's user-mode networking accepts it fine because the "network" is entirely virtual inside QEMU.
Q: Why no TCP? Couldn't we add it?
TCP requires: connection state (CLOSED, SYN_SENT, ESTABLISHED, FIN_WAIT_1, FIN_WAIT_2, TIME_WAIT, CLOSE_WAIT, LAST_ACK — 11 states), sequence numbers, ACK tracking, retransmission timers, window sizing, and congestion control. Each of those is a module by itself. UDP first is the right order — you learn IP framing without state machine overhead, then add TCP state on top.
Q: What does polled I/O mean vs interrupt-driven?
Polled: the CPU repeatedly asks "any packets yet?" on every timer tick regardless of NIC activity. Interrupt-driven: the NIC asserts IRQ only when a packet arrives; the CPU handles it, then goes back to other work. Polled is simpler but wastes CPU cycles checking an empty queue. Linux's NAPI is hybrid: interrupt-driven to wake, then polled in a budget loop to drain the queue before going back to sleep.

09 — What's Next

Module 27 — Device Driver Framework

Right now the NE2000 is hardcoded into the kernel. Module 27 introduces a driver registration table: driver_register(&ne2000_driver). The kernel calls driver_probe() for each registered driver, and drivers expose themselves through the VFS as /dev/eth0. This is how Linux's driver model works — and it's why you can run the same kernel binary on machines with completely different hardware.
