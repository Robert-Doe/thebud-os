The Shell

01 — The Big Analogy

Head First Moment

A shell is like a hotel concierge. Guests (you) walk up and say "I want to see a list of files" or "run this program." The concierge (shell) listens, figures out what you mean, calls the right department (filesystem, process scheduler, VGA driver), and reports back. The concierge doesn't do the work — it just coordinates.

Your shell is just a C function that loops: read a line from the keyboard → split it into tokens → match the first token to a known command → call the right kernel function → print the result → repeat.

02 — The Shell Loop

/* shell.c — the entire shell in one function */
void shell_main(void) {
    char line[256];
    char *argv[16];

    for (;;) {
        kprintf("BobSH> ");
        readline(line, sizeof(line));   /* keyboard_getchar loop */
        if (line[0] == '\0') continue;

        int argc = tokenize(line, argv, 16); /* split on spaces */
        if (argc == 0) continue;

        if      (strcmp(argv[0], "help") == 0) cmd_help();
        else if (strcmp(argv[0], "ls")   == 0) cmd_ls();
        else if (strcmp(argv[0], "cat")  == 0) cmd_cat(argv[1]);
        else if (strcmp(argv[0], "run")  == 0) cmd_run(argv[1]);
        else kprintf("Unknown command: %s\n", argv[0]);
    }
}
readline() uses keyboard_getchar()

readline() calls keyboard_getchar() (Module 9) in a loop, echoing each character to the VGA driver, handling backspace, and stopping at newline. It's only about 20 lines — but it's the moment keyboard input and VGA output are wired together into something interactive.

/* cmd_ls: iterate BobFS inodes and print names/sizes */
static void cmd_ls(void) {
    for (int i = 0; i < 32; i++) {
        if (!super.inodes[i].valid) continue;
        kprintf("  %-20s %u bytes\n",
                super.inodes[i].name,
                super.inodes[i].size);
    }
}

/* cmd_cat: read file into temp buf, print it */
static void cmd_cat(const char *name) {
    char buf[4096];
    int n = fs_read(name, buf, sizeof(buf) - 1);
    if (n < 0) { kprintf("cat: file not found\n"); return; }
    buf[n] = '\0';
    kprintf("%s\n", buf);
}

04 — The Tokenizer

/* Split "cat hello.txt" into argv = ["cat", "hello.txt", NULL] */
static int tokenize(char *line, char **argv, int max) {
    int argc = 0;
    char *p = line;
    while (*p && argc < max - 1) {
        while (*p == ' ') p++;    /* skip spaces */
        if (!*p) break;
        argv[argc++] = p;         /* token starts here */
        while (*p && *p != ' ') p++;  /* find end of token */
        if (*p) *p++ = '\0';      /* null-terminate the token */
    }
    argv[argc] = NULL;
    return argc;
}
Why Not strtok?

Our kernel has no C standard library — no string.h, no strtok. We write everything ourselves. That's the point. Once you've written a tokenizer and a strcmp from scratch, you understand exactly what those library functions do internally.

06 — Brain Exercise

Sharpen Your Pencil

Question: The shell is a process that calls keyboard_getchar(), which spins (hlt) until a key arrives. While the shell is waiting for input, what are the other processes doing?

Think about the scheduler. The shell is blocked in hlt inside its IRQ handler. When the timer IRQ fires, does it preempt the shell? What state should the shell be in while it's waiting for keyboard input — RUNNING or WAITING?

There Are No Dumb Questions

Q: Is our shell a "real" shell like bash?
Structurally, yes — it's the same read-parse-execute loop. What it lacks: pipes (ls | grep — Module 20), redirection (> / <), environment variables, job control (background processes), and a real PATH. Each of those is a module's worth of work. But the core loop is identical to bash's.
Q: What happens if I type more than 256 characters?
Buffer overflow. readline() should stop at 255 characters and null-terminate — check that the implementation has that bound check. A kernel shell doesn't have to be hardened (only the kernel itself can type into it), but it's still good practice.
