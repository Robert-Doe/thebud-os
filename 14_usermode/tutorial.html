MODULE 14 — PHASE 2

User Mode (Ring 3)

Until now every process runs with full kernel privilege. Module 14 changes that permanently: the CPU enforces two worlds — ring 0 (kernel, trusted) and ring 3 (user, untrusted). A user program that touches kernel memory gets a hardware fault, not a chance.

01 — The Big Analogy

Head First Moment

Think of a nuclear power plant. There's the control room (ring 0, kernel) where trained engineers can touch every dial and valve. And there's a visitor gallery (ring 3, user space) separated by thick glass — visitors can see things and press limited buttons, but they physically cannot reach the critical equipment. If they try to climb over the barrier, an alarm sounds (General Protection Fault) and security arrives.

The "thick glass" is enforced not by your code but by the CPU itself. That's what makes ring 3 actually safe.

02 — Three Things That Make Ring 3 Work

1. User-mode GDT segments (DPL=3)

Already done in Module 4. Selector 0x1B = user code (DPL=3), 0x23 = user data (DPL=3). When the CPU runs code with CS=0x1B, it's in ring 3 and any attempt to load CS=0x08 (kernel code) causes a #GP.

2. The TSS (Task State Segment)

When a ring-3 syscall fires, the CPU needs to switch to a kernel stack. It looks up TSS.esp0 — the ring-0 stack pointer for the current process. We update TSS.esp0 on every context switch.

/* tss.c */
typedef struct { /* only the fields we care about */
    uint32_t reserved0;
    uint32_t esp0;     /* kernel stack pointer for ring-3→0 transitions */
    uint32_t ss0;      /* kernel stack segment (0x10) */
    /* ... 23 more fields we zero out ... */
} __attribute__((packed)) tss_t;

void tss_set_kernel_stack(uint32_t esp) {
    tss.esp0 = esp; /* called before switching to a ring-3 process */
}

3. Jumping to ring 3 with iret

You can't just jmp to a ring-3 address — that would stay in ring 0. The only way to enter ring 3 is with iret, which simultaneously restores EIP, CS (to 0x1B), EFLAGS, ESP, and SS (to 0x23) from the stack.

/* Build a fake iret frame on the kernel stack, then iret into ring 3 */
void jump_to_usermode(uint32_t entry, uint32_t user_stack) {
    __asm__ volatile (
        "mov $0x23, %%ax\n"   /* user data selector */
        "mov %%ax, %%ds\n"
        "mov %%ax, %%es\n"
        "push $0x23\n"        /* SS  — user stack segment */
        "push %1\n"           /* ESP — user stack top */
        "push $0x202\n"       /* EFLAGS: IF=1 (interrupts enabled) */
        "push $0x1B\n"        /* CS  — user code selector */
        "push %0\n"           /* EIP — user entry point */
        "iret\n"
        : : "r"(entry), "r"(user_stack) : "eax"
    );
}

03 — The Privilege Transition Stack

Ring 3 → Ring 0 (syscall / interrupt)

CPU saves: SS, ESP, EFLAGS, CS, EIP onto the kernel stack (from TSS.esp0). These 5 extra words are what makes the ring-3 interrupt frame larger than a ring-0 one — your interrupt_frame struct has user_esp and user_ss at the top for exactly this reason.

Ring 0 → Ring 3 (iret)

CPU pops EIP, CS, EFLAGS, ESP, SS from the kernel stack and resumes execution in ring 3. The stack pointer switches to the user stack automatically. The kernel stack is left clean, ready for the next syscall.

04 — The User Program

/* user_prog.c — runs at ring 3, at address 0x400000 */
void user_main(void) {
    /* Can call syscalls — they go through int 0x80 */
    sys_write("Hello from Ring 3!\n");
    int pid = sys_getpid();
    sys_write("I am a user process.\n");

    /* Try to access kernel memory — this WILL fault */
    /* *(uint32_t*)0x1000 = 0;  ← causes #GP, process killed */

    sys_exit(0);
}

/* user_entry.asm — minimal startup for user code */
global user_entry
user_entry:
    call user_main
    ; if user_main returns, call sys_exit(0)
    mov eax, 0   ; SYS_EXIT
    mov ebx, 0
    int 0x80
User stack lives at 0x800000

The kernel sets up a user stack at a fixed virtual address (e.g. 0x800000) before jumping to ring 3. The user code's ESP points there. This stack is mapped PAGE_USER so ring-3 can access it. The kernel stack is at a different address and NOT mapped PAGE_USER — user code can't touch it.

There Are No Dumb Questions

Q: What's CPL vs DPL?
CPL (Current Privilege Level) is in bits 0-1 of the CS register — it's the privilege level your code is currently running at (0 = kernel, 3 = user). DPL (Descriptor Privilege Level) is baked into a GDT or IDT entry and says the minimum privilege needed to use it. Access is allowed when CPL ≤ DPL. That's why the syscall gate needs DPL=3 — user code (CPL=3) can trigger it.
Q: Why not have more than two rings?
x86 has 4 rings (0–3). Real-mode OSes sometimes used ring 1/2 for device drivers. But modern OSes (Linux, Windows, macOS) only use ring 0 and ring 3. The reason: VMMs (hypervisors) now use ring -1 (VMX root mode) for the host, pushing everything up. Rings 1 and 2 are legacy and complicate the model without adding practical security.

07 — What's Next

Up Next: Module 15 — Per-Process Address Spaces

Right now every process shares the same page directory. Module 15 gives each process its own CR3 — its own private virtual address space. Process A can't read process B's memory even if they use the same virtual address. The kernel is mapped into every address space at the same location so syscalls still work.
