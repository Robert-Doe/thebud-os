One Address,
Three Disguises

When your instruction says "read the value at this address," that address is lying to you three times before it ever touches a memory chip. It starts as a logical address, gets translated into a linear address, and only then becomes a physical address — the one and only kind RAM actually understands. This is the story of that journey, and the two hardware circuits that make it happen on every single memory access, billions of times a second.

01 — Three Words People Use Loosely

Programmers Say "Address." The CPU Hears Three Different Things.

Say you write int x = arr[5]; in C. That "address of arr[5]" is not one fixed concept — it changes shape three times on its way to becoming an actual electrical signal on a RAM chip's pins. This isn't academic pedantry: Intel's 80×86 architecture builds this three-stage journey directly into silicon, and Linux's entire memory-protection story depends on understanding exactly where each stage happens.

📫 Logical Address

What your instruction actually contains: a segment + an offset. The "apartment number" — meaningless without knowing which building.

🗺️ Linear Address

A single flat 32-bit number, 0 to 4GB. The "citywide grid coordinate" — one unified numbering system, still not real RAM.

⚡ Physical Address

The actual signal sent down the address pins to a real memory chip. The "GPS coordinate" a memory cell physically sits at.
💡 The One-Sentence Version
Logical → (Segmentation Unit) → Linear → (Paging Unit) → Physical. Two separate hardware circuits, wired in series, and your program — and even the OS, most of the time — never has to do this math by hand.
02 — Stage Zero

The Logical Address: Segment + Offset

Every machine-language instruction that touches memory doesn't embed one raw number — it embeds two pieces: which segment it's talking about, and the offset (distance) from the start of that segment. This is a direct fossil of the old 80×86 segmented architecture that MS-DOS and early Windows programmers had to think about explicitly.

Think of a segment like a named building, and the offset like "the 12th room from the front door." segment:offset only makes sense once you know which building you're standing in front of — which is precisely why this can't be the final address. It's relative, not absolute.

Why keep segments at all? They let the OS give a code segment, a data segment, and a stack segment separate identities, sizes, and — crucially, as you'll see in the GDT piece — separate privilege levels, all before paging-based protection even gets involved.
03 — Stage One

The Linear Address: One Flat Number

The segmentation unit — a real hardware circuit inside the CPU, not a piece of OS code — takes your segment:offset pair and produces a single, unsigned 32-bit integer: the linear address, also called the virtual address. It ranges from 0x00000000 to 0xffffffff, addressing up to 4,294,967,296 individual bytes (4 GB).

This is the point where all the messy "which building" bookkeeping disappears into one uniform, flat numbering system — every byte in the process's addressable world now has exactly one linear address, full stop.

What the segmentation unit computes Linear Address = Segment Base Address + Offset "Segment Base Address" comes from a Segment Descriptor — the subject of the next two pages in this series.
04 — Stage Two

The Physical Address: What RAM Actually Sees

A linear address still isn't real — it's a coordinate in an abstract 4GB space that might not correspond 1-to-1 with where data actually lives in physical RAM (especially once swapping and multiple processes enter the picture). The paging unit, a second hardware circuit, transforms the linear address into a physical address: a 32-bit or 36-bit unsigned integer that corresponds directly to electrical signals sent along the microprocessor's address pins to the memory bus.

This is the address a RAM chip actually receives. Nothing more abstract happens after this point — it's the end of the line.

05 — Watch It Happen

The Full Pipeline: The MMU

Both circuits together — the segmentation unit and the paging unit — are collectively called the Memory Management Unit (MMU). Every memory reference your CPU makes flows through both stages, in hardware, without a single instruction of OS code running in between (unless something goes wrong, like a page fault, which we've covered as an exception trap in the earlier piece on traps and PCBs).

  2. Segmentation unit adds the segment's baseLooks up the segment's Segment Descriptor (from the GDT or LDT — next articles), reads its Base field, and adds it to the offset to produce a 32-bit linear address.
  3. Paging unit walks the page tablesSplits the linear address into pieces used to walk in-memory page tables (owned by the currently running process, per its PCB's memory pointer) and resolve the actual physical page frame.
  4. Physical address hits the busThe final address is placed on the memory bus, the memory arbiter grants access, and the RAM chip responds with the actual byte(s).
💡 Why Two Separate Circuits Instead of One?
Segmentation gives the OS a cheap way to express logical groupings with different rights (code vs. data vs. stack, at different privilege levels) — it's the first line of protection. Paging gives the OS a cheap way to express flexible, page-granular physical placement — letting physical RAM be scattered, shared, swapped, and remapped, invisibly to the running program. Linux, notably, uses segmentation minimally (flat segments covering the whole address space) and leans almost entirely on paging for real protection — but the segmentation stage still runs on every access, because the hardware pipeline is fixed.
06 — The Detail Everyone Forgets

The Memory Arbiter: Sharing One Chip

Here's a subtlety worth having: even a single-core machine has more than one thing trying to touch RAM. DMA controllers — specialized processors that move data (like a disk transfer) without bothering the CPU — operate concurrently with the CPU itself. In multiprocessor systems, multiple CPUs share the same RAM chips directly.

Since a RAM chip can only actually service one read or write at a time, a hardware circuit called the memory arbiter sits between the bus and every RAM chip, granting access to whoever's free and delaying whoever's not — invisibly, entirely in hardware, never surfaced to the programmer.

🧠 Why This Matters Later
The memory arbiter is the unglamorous reason "shared memory between processes" (from the PCB/threads piece) doesn't cause electrical chaos even when two processes race to write the same physical page at the same instant — the arbiter serializes the raw electrical access, though it does nothing to stop the logical race condition, which is still the programmer's job to guard with a semaphore.
07 — Quick Reference

Glossary & Key Terms

Logical Address
A segment + offset pair embedded in a machine instruction — relative, meaningless without the segment's identity.
Linear Address (Virtual Address)
A flat 32-bit unsigned integer (0x00000000–0xffffffff) produced by the segmentation unit.
Physical Address
The final 32/36-bit address placed on the memory bus — what a RAM chip actually receives.
Segmentation Unit
Hardware circuit that adds a segment's base address to an offset, converting logical → linear.
Paging Unit
Hardware circuit that walks page tables to convert linear → physical.
MMU
Memory Management Unit — the segmentation unit and paging unit together.
Memory Arbiter
Hardware circuit serializing concurrent access requests (from CPUs and DMA controllers) to a single RAM chip.
DMA Controller
A specialized processor moving data to/from memory independently of the CPU, still subject to the memory arbiter.
