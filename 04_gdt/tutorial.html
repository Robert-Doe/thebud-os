The GDT

The Global Descriptor Table is the OS's zoning law. It tells the CPU which parts of memory are for the kernel and which are for user programs — and enforces it in hardware.

01 — The Big Analogy

Head First Moment

Imagine a city with two zones: an industrial zone (kernel) and a residential zone (user programs). The zoning board (the GDT) keeps a registry of which areas are which, and who's allowed in. The police (CPU) check this registry on every memory access. Try to drive a residential car into the industrial zone? Stopped at the gate — General Protection Fault.

That's the GDT. A flat table of "segment descriptors" that the CPU uses to decide whether your code is allowed to do what it's trying to do.

02 — What a GDT Entry Contains

Each GDT entry is 8 bytes, encoding a base address, a limit, and a bunch of permission flags. The important ones:

struct gdt_entry {
    uint16_t limit_low;    /* segment size (low 16 bits) */
    uint16_t base_low;     /* base address (low 16 bits) */
    uint8_t  base_mid;     /* base address (middle 8 bits) */
    uint8_t  access;       /* Present | DPL | type flags */
    uint8_t  granularity;  /* limit high nibble + flags (G, D/B) */
    uint8_t  base_high;    /* base address (high 8 bits) */
};
The Access Byte Is Everything

The access byte packs: P|DPL|S|Type. P=1 means the segment is present. DPL is the privilege level (0=kernel, 3=user). S=1 for code/data segments. Type bits say whether it's executable (code) or not (data). Set DPL=3 and that segment can only be used from ring 3.

03 — BobOS's Five GDT Entries

SelectorNameRingPurpose
0x00Null descriptor—Required by CPU spec. Must be all zeros. Loading a null selector causes a #GP.
0x08Kernel Code0All kernel C code runs under this. Executable, ring 0, base=0, limit=4GB.
0x10Kernel Data0Kernel stack and data. Writable, ring 0, base=0, limit=4GB.
0x1BUser Code3User programs run here. DPL=3. The 0x3 in 0x1B = RPL bits indicating ring 3.
0x23User Data3User stack and data. Writable, DPL=3.
Why 0x1B and not 0x18?

Segment selectors have the privilege level baked into the lowest 2 bits (called the RPL — Requested Privilege Level). 0x18 = GDT entry 3, RPL=0. 0x1B = GDT entry 3, RPL=3. When the CPU checks a selector's permission, it uses max(CPL, RPL) — so user code must use a selector with RPL=3 or it can escalate its own privilege.

04 — Loading the GDT

/* gdt.c */
static struct gdt_entry gdt[5];
static struct { uint16_t limit; uint32_t base; } __attribute__((packed)) gdtr;

void gdt_init(void) {
    gdt_set_entry(0, 0, 0, 0, 0);                  /* null */
    gdt_set_entry(1, 0, 0xFFFFF, 0x9A, 0xCF);      /* kernel code */
    gdt_set_entry(2, 0, 0xFFFFF, 0x92, 0xCF);      /* kernel data */
    gdt_set_entry(3, 0, 0xFFFFF, 0xFA, 0xCF);      /* user code DPL=3 */
    gdt_set_entry(4, 0, 0xFFFFF, 0xF2, 0xCF);      /* user data DPL=3 */

    gdtr.limit = sizeof(gdt) - 1;
    gdtr.base  = (uint32_t)&gdt;
    __asm__ volatile ("lgdt %0" : : "m"(gdtr));     /* one instruction */

    /* reload segment registers to use new GDT */
    __asm__ volatile (
        "mov $0x10, %%ax\n"
        "mov %%ax, %%ds\n mov %%ax, %%es\n mov %%ax, %%ss\n"
        "ljmp $0x08, $1f\n 1:\n" : : : "eax"
    );
}
Granularity Byte 0xCF

0xCF = 1100_1111. The top bit (G=1) means the limit is in 4KB pages, not bytes. So limit 0xFFFFF × 4KB = 4GB. The second bit (D/B=1) means 32-bit default operand size. These two bits together say "4GB flat 32-bit segment."

06 — Brain Exercise

Sharpen Your Pencil

Question: We set base=0 and limit=4GB for every segment. That means all segments cover the entire address space. If every segment is identical (except DPL), what's actually protecting memory from user programs?

The answer is: the GDT alone doesn't protect much in a flat-memory model. The real protection comes from something we build in Module 7. What is it?

There Are No Dumb Questions

Q: Why not just have one big segment covering all of memory?
You could, and some OS designs do this (it's called a "flat model"). The reason we have separate kernel/user segments is privilege separation — the DPL field on the segment controls who can load that selector. A ring-3 process that tries to load CS=0x08 (kernel code) gets a General Protection Fault. The segment separation is the CPU-level enforcement of ring boundaries.
Q: Do modern OSes still use the GDT?
Yes, but in a minimal way. 64-bit long mode largely ignores segment bases/limits (they're treated as zero/max). But the GDT still exists and is still required — particularly for the TSS entry (Module 10) and for the DPL of CS to distinguish kernel/user mode during syscalls.
