01 — The 16-Bit ID Card

The Segment Selector

A logical address's "segment" half isn't the segment's actual data — it's a compact 16-bit pointer to a description of the segment, called a Segment Selector. Three fields are packed into those 16 bits.

index
bits 15–3 (13 bits)
TI
bit 2
RPL
bits 1–0
index13 bits
Which numbered slot to look up in the descriptor table — this is literally "row number" into an array of Segment Descriptors. This is the star of the dedicated GDT article coming next.
TI (Table Indicator)1 bit
Which table to search: 0 means the GDT (the shared, global catalog), 1 means the LDT (a process's own private catalog).
RPL (Requestor Privilege Level)2 bits
The privilege level being requested for this particular access — checked against the descriptor's own minimum privilege before access is allowed.
🧠 The Aha Moment
A segment selector doesn't carry any actual segment information itself — no base address, no size, no permissions. It's purely an address of an address: "go look at slot index in table TI, and treat this access as happening at privilege level RPL." All the real substance lives in the Segment Descriptor it points to.
02 — Where Selectors Actually Live

The Six Segmentation Registers

To avoid re-fetching a selector from memory on every single instruction, the CPU keeps six dedicated registers whose only job is to hold a currently active Segment Selector: cs, ss, ds, es, fs, gs. A program can reuse the same register for different purposes over time by saving its value and restoring it later — but three of the six have fixed, specific jobs.

RegisterPurpose
csCode segment register — points to the segment holding the currently executing instructions.
ssStack segment register — points to the segment holding the current program's stack.
dsData segment register — points to the segment holding global and static data.
es, fs, gsGeneral purpose — free for the program or OS to point at arbitrary data segments.
🔑 cs Is Doing Double Duty
The cs register carries a secret extra passenger: a 2-bit field specifying the CPU's Current Privilege Level (CPL) — the actual live privilege the CPU is running at right now. This is not a separate lookup; it's baked directly into whichever code segment is currently active. Wherever cs points, that's your current ring.
03 — The Callback You Were Waiting For

CPL: Rings, Made Concrete

Remember Ring 0 and Ring 3 from the very first article in this series? Here's exactly where that abstraction becomes a real, physical 2-bit field. The CPL uses value 0 for the highest privilege level and 3 for the lowest. Linux — like almost every general-purpose OS — uses only these two extremes, and gives them names you already know:

CPL = 0

Called Kernel Mode in Linux. Full privilege — this is Ring 0, restated in the exact hardware field that enforces it.

CPL = 3

Called User Mode in Linux. Restricted privilege — this is Ring 3, restated the same way.

So when the earlier articles said "the CPU checks a privilege flag before running dangerous instructions," this 2-bit field inside cs is that flag, made concrete. Changing CPL isn't something ordinary code does directly — it happens exactly at the moments you already know about: booting into Ring 0, executing a trap instruction like syscall, or handling a hardware interrupt.

04 — The Full Record

The Segment Descriptor

Every segment is described by an 8-byte Segment Descriptor — the "full record card" a selector's index field points to. This is where the actual substance lives: where the segment starts, how big it is, what it's for, and who's allowed to use it.

FieldWhat It Holds
BaseThe linear address of the segment's first byte — this is exactly the "Segment Base Address" from the translation formula in the previous article.
LimitThe offset of the segment's last byte, bounding its length: up to 1MB (byte granularity) or up to 4GB (4KB granularity, via the G flag).
GGranularity flag — 0 means Limit is in bytes, 1 means Limit is in 4096-byte units.
SSystem flag — cleared (0) for system segments like the LDT or a TSS; set (1) for ordinary code/data segments.
TypeThe segment's type and access rights (code? data? readable? writable? more below).
DPLDescriptor Privilege Level — the minimum CPL required to access this segment. DPL 0 = Kernel-Mode-only; DPL 3 = accessible at any CPL.
PSegment-Present flag — whether the segment is currently in memory. Linux always sets this to 1; it never swaps out whole segments.
D/BSet if offsets in this segment are 32 bits wide, cleared if 16 bits.
AVLAvailable for OS use — ignored entirely by Linux.
💡 DPL vs RPL — Don't Mix These Up
DPL lives in the descriptor and is fixed: "the minimum privilege anyone needs to touch this segment." RPL lives in the selector and changes per access: "the privilege level this particular access claims to be happening at." The CPU checks both against the live CPL before allowing access — DPL is the lock, RPL and CPL are what gets compared against the key.
05 — Three Flavors

Kinds of Segment Descriptor

Code Segment Descriptor
S flag set (non-system). Describes a segment holding executable instructions. Can live in the GDT or an LDT.
Data Segment Descriptor
S flag set. Describes ordinary data. Stack segments are actually implemented as regular data segments — there's no separate "stack descriptor" type.
Task State Segment Descriptor (TSSD)
S flag cleared (system segment). Describes a Task State Segment — a region used to save processor register contents. Can only appear in the GDT, never an LDT.

Notice the pattern already forming: some descriptors go in a table every process can see (the GDT), while others can optionally live in a table private to one process (the LDT). What those two tables actually are, how the CPU finds them, and exactly how a selector's index turns into a real memory address — that's the entire subject of the next article, dedicated fully to the GDT.

06 — Quick Reference

Glossary & Key Terms

Segment Selector
16-bit value (index + TI + RPL) that identifies which Segment Descriptor to use — held in a segmentation register.
TI (Table Indicator)
1-bit field in a selector choosing between the GDT (0) and the current LDT (1).
RPL (Requestor Privilege Level)
2-bit field in a selector stating the privilege level this access is being made at.
cs, ss, ds, es, fs, gs
The six segmentation registers; cs and ss have fixed roles (code, stack), ds is conventionally data, the rest are general purpose.
CPL (Current Privilege Level)
2-bit field inside cs giving the CPU's live privilege level right now — 0 (Kernel Mode) or 3 (User Mode) on Linux.
Segment Descriptor
8-byte record describing one segment: Base, Limit, G, S, Type, DPL, P, D/B, AVL.
DPL (Descriptor Privilege Level)
Minimum CPL required to access a given segment, fixed inside its descriptor.
TSS / TSSD
Task State Segment — stores saved processor register contents; described by a system-type descriptor found only in the GDT.
